# Project Setup

> How to scaffold a new Java project with Maven or Gradle, using the standard directory layout and running it end to end.

---

## Prerequisites

- A JDK installed and on the `PATH` (see [Installation](installation.md))
- Maven **or** Gradle available (both can be installed via SDKMAN!)
- A terminal and a text editor or IDE

---

## Steps

### 1. Install a build tool (if needed)

```bash
sdk install maven
# or
sdk install gradle
```

Both projects use the same standard directory layout:

```
my-app/
├── pom.xml or build.gradle.kts
└── src/
    ├── main/
    │   ├── java/         # production source
    │   └── resources/    # config files, static assets
    └── test/
        ├── java/         # test source
        └── resources/    # test fixtures
```

### 2a. Generate a Maven project

Use the Maven archetype to scaffold a project non-interactively.

```bash
mvn archetype:generate \
  -DgroupId=com.example \
  -DartifactId=my-app \
  -DarchetypeArtifactId=maven-archetype-quickstart \
  -DarchetypeVersion=1.4 \
  -DinteractiveMode=false

cd my-app
```

Set the Java version and add dependencies in `pom.xml`:

```xml
<properties>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
</properties>

<dependencies>
    <dependency>
        <groupId>org.junit.jupiter</groupId>
        <artifactId>junit-jupiter</artifactId>
        <version>5.10.2</version>
        <scope>test</scope>
    </dependency>
</dependencies>
```

### 2b. Or generate a Gradle project

Gradle's `init` task scaffolds interactively — or pass flags to skip the prompts.

```bash
mkdir my-app && cd my-app
gradle init \
  --type java-application \
  --dsl kotlin \
  --test-framework junit-jupiter \
  --package com.example \
  --project-name my-app
```

This produces a `build.gradle.kts`:

```kotlin
plugins {
    application
}

java {
    toolchain { languageVersion = JavaLanguageVersion.of(21) }
}

dependencies {
    testImplementation("org.junit.jupiter:junit-jupiter:5.10.2")
    testRuntimeOnly("org.junit.platform:junit-platform-launcher")
}

application {
    mainClass = "com.example.App"
}

tasks.test { useJUnitPlatform() }
```

### 3. Write the entry point

```java
// src/main/java/com/example/App.java
package com.example;

public class App {
    public static void main(String[] args) {
        System.out.println("Hello from my-app");
    }
}
```

### 4. Build and run

```bash
# Maven
mvn compile
mvn exec:java -Dexec.mainClass=com.example.App
mvn test

# Gradle (the wrapper ./gradlew is generated by gradle init)
./gradlew build
./gradlew run
./gradlew test
```

### 5. Commit the build wrapper

Gradle generates a wrapper (`gradlew`, `gradlew.bat`, `gradle/wrapper/`). Commit it so everyone builds with the same Gradle version. For Maven, the equivalent is the Maven Wrapper:

```bash
mvn wrapper:wrapper
```

## Verification

```bash
# Maven: a JAR appears under target/
ls target/*.jar

# Gradle: a JAR appears under build/libs/
ls build/libs/*.jar

# Running prints the greeting
./gradlew run            # or: mvn exec:java -Dexec.mainClass=com.example.App
# Hello from my-app

# Tests pass
./gradlew test           # or: mvn test
```

## Common issues

| Symptom | Likely cause | Fix |
|---|---|---|
| `release version 21 not supported` | Build tool running on an older JDK | Point `JAVA_HOME` at JDK 21, or lower `maven.compiler.release` |
| `package com.example does not exist` | Directory does not match the package | Ensure `src/main/java/com/example/` matches `package com.example;` |
| Tests are not discovered | JUnit Platform not enabled (Gradle) | Add `tasks.test { useJUnitPlatform() }` |
| `mvn: command not found` | Maven not installed / not on PATH | `sdk install maven` or add it to PATH |
| Gradle downloads a new distribution every build | Wrapper not committed | Commit `gradlew` and `gradle/wrapper/` |
